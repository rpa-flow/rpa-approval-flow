# Plano de fases — NFS-e, NF-e e CT-e

Objetivo: receber os três tipos via API e disponibilizá-los no portal de aprovação. A referência de decisões é [Fase 0 consolidada](f0-consolidado.md). Coleta externa e lançamento no Minerion ficam fora deste plano.

| Fase | Documento | Situação |
|---|---|---|
| 0 — Definição | [Fase 0 consolidada](f0-consolidado.md) | Planejamento concluído; verificações remanescentes registradas |
| 1 — Domínio e dados | [Fase 1](fase-1-dominio-dados.md) | Planejada |
| 2 — API de recebimento | [Fase 2](fase-2-api.md) | Planejada; depende da Fase 1 |
| 3 — Portal e workflow | [Fase 3](fase-3-portal-workflow.md) | Planejada; depende das Fases 1 e 2 |
| 4 — Verificação e ativação | [Fase 4](fase-4-validacao-ativacao.md) | Planejada; depende das fases anteriores |

Cada fase exige verificação proporcional e entrega com evidências. Planejamento não é implementação nem homologação. Mudanças materiais descobertas durante a execução devem voltar à especificação antes de serem aplicadas. Os documentos `spec.md`, `review.md` e `f0-contracts.md` preservam histórico; em caso de divergência prevalecem as decisões atualizadas em `f0-consolidado.md`.
